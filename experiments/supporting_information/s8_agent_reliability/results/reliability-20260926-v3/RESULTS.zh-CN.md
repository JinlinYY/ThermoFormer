# Agent 可靠性实验结果

已完成 72 次真实 DeepSeek 请求任务：15 条等价需求、9 条异常需求，各重复 3 次。
API 实际返回模型名为 `deepseek-flash`。三个案例的原论文计算结果均在预设容差内复现，级数选择不变。
论文正文与 SI 未修改。

## 主要结果

|指标|二元精馏|萃取精馏|错流萃取|合计|
|---|---:|---:|---:|---:|
|完整需求编译正确|15/15|15/15|15/15|45/45|
|工具计划正确|15/15|15/15|15/15|45/45|
|工具执行正确|15/15|15/15|15/15|45/45|
|结果与原论文一致|15/15|15/15|15/15|45/45|
|证据报告通过|15/15|15/15|15/15|45/45|
|LLM 原始澄清正确|3/9|0/9|9/9|12/27|
|系统拦截异常输入|9/9|9/9|9/9|27/27|

45 次完整需求中，3 次实际执行了冻结协议的数值计算，其余 42 次复用带来源与哈希的数值文件。
缓存复用验证的是输入等价性、工具编排与结果绑定。每个案例包含 5 条独立表达，三次重复不增加化学体系数量。

“LLM 原始澄清正确”要求其状态为 `clarify`，并指出正确的问题字段和类型。
另有 6 次请求已列出正确问题，却同时给出 `ready` 状态，因此没有计为正确澄清。
其余漏检包括未注明质量/摩尔基准、缺少目标值及组成不归一。程序校验在数值工具前拦住了这些情况。
这说明可靠执行依赖 LLM 与确定性输入检查的配合。

证据报告包含 180 项结构化结论绑定，本评测中没有缺失必要证据或不受支持的结论。
该指标限定在已登记的结论集合与证据 ID 中；不能外推为开放文本生成的零幻觉保证。

## 三个案例的数值核对

|案例|原论文结果|本轮复算|
|---|---|---|
|二元精馏|PCHIP 12 级、线性插值 13 级，进料第 6 级|级数与进料位置完全一致；保持原精确回流比及 16 点组成网格|
|萃取精馏|183 级纯度 99.508632 mol%，回收率 98.008502%；182 级略低于目标|两项指标均复现；182/183 级未舍入达标判断不变；最大指标差约 1.01e-13|
|错流萃取|三级等分，苯回收率 71.1506%，正庚烷保留率 81.1500%|原 1–4 级扫描及 22 个分配候选复现，最大指标差约 8.88e-16|

原权重、论文求解器、实验数据和归档结果没有覆写。哈希、来源、ggnn39 环境、缓存绑定和异常输入拦截审计通过。
这些比较证明原论文计算协议可重现；物理准确性和工程适用范围仍依赖既有证据。
萃取精馏轨迹超出当前 17 个实验测量点覆盖的限制仍然保留。

## 计算成本

- 最终 v3：117 次 API 调用，API 返回的总 token 数 189,708。
- 72 次任务累计记录耗时约 180.9 s；42 次缓存完整任务的耗时中位数约 2.57 s。
- 源文件与提示词在本轮运行前冻结；这是三个预定义化学体系上的协议评估，不代表独立盲测或跨体系泛化实验。

新增输入/报告边界与相关既有逻辑合计 37 项测试通过；本轮新增 Python 文件的 Ruff 与严格 mypy 检查通过。
